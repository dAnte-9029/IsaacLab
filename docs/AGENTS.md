# Project Documentation

Write documents only when requested or when a substantial change needs a short, durable explanation. Existing `PROJECT_STATE.md`, handoffs, ADRs, plans, and audits are useful references, not mandatory artifacts of every coding task.

Keep implemented behavior, hypotheses, assumptions, and experimental evidence distinct. Do not rewrite accepted historical decisions as if they were always different; mark superseded decisions when needed.

Cite specific code, configurations, plots, or runs for important scientific claims. Distinguish a numerically working model, prescribed-motion aerodynamic comparison, free-body simulation, controller benchmark, sim-to-real evidence, and actual flight validation.

Avoid boilerplate templates, exhaustive handoff checklists, and duplicative status reports. If documentation is the deliverable, make it substantive and concise.
