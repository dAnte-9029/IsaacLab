# Effective Wrench Model vs. DeLaurier Model Comparison Plan

Date: 2026-05-13

## Goal

This note records the proposed experiment design for comparing two aerodynamic models on the same real flapping-wing flight logs:

- The current IsaacLab physics model based on the DeLaurier strip-theory formulation.
- The learned neural-network model trained from real flight logs to predict effective aerodynamic wrench.

The main scientific question is whether the learned effective-wrench model gives predictions that are closer to the real flight trajectory and the inferred real-flight wrench than the DeLaurier-based model.

## Core Difficulty

The two models do not expose the same internal physical quantities.

The DeLaurier model computes aerodynamic contributions such as normal force, lift/thrust-like components, and wing loads through a strip-theory pipeline. In IsaacLab, these loads are eventually converted into a net body-frame force and moment and applied to the robot base.

The learned model directly predicts a six-axis effective aerodynamic wrench:

```text
w_b = [F_x, F_y, F_z, M_x, M_y, M_z]
```

where the wrench is expressed in the vehicle body frame.

Therefore, the fair comparison should not be performed on intermediate quantities such as lift or thrust. The common comparison interface should be the final body-frame net wrench applied to the vehicle.

## Recommended Experiment Structure

### 1. Main Experiment: Teacher-Forced One-Step Wrench Prediction

For each timestamp in a held-out real flight log, both models receive the same recorded state and the same recorded control inputs. Each model predicts the body-frame net wrench at that timestamp. The predictions are compared against the effective-wrench labels reconstructed from the real trajectory.

This is the cleanest experiment because:

- Both models see the same state and control input.
- The comparison is not affected by controller compensation.
- The comparison is not strongly affected by rollout instability or accumulated integration error.
- The target quantity is the same six-axis body-frame wrench for both models.

The reported metrics should include per-axis RMSE and R2 for:

```text
F_x, F_y, F_z, M_x, M_y, M_z
```

Longitudinal channels and lateral-directional channels should also be summarized separately:

- Longitudinal / pitch-related: `F_x`, `F_z`, `M_y`.
- Lateral-directional: `F_y`, `M_x`, `M_z`.

### 2. Secondary Experiment: Short-Horizon Open-Loop Rollout

The simulator is initialized from a real flight-log state. The recorded real control inputs are then replayed open-loop for a short horizon, for example 0.5 to 2 seconds. The same initial state and same controls are used for both aerodynamic backends:

- DeLaurier backend.
- Learned effective-wrench backend.

The rollout is compared against the real trajectory using:

- Position error.
- Velocity error.
- Attitude error.
- Angular-rate error.

This experiment is more intuitive than one-step wrench prediction because it directly asks whether the model produces a trajectory closer to the real flight. However, it should be interpreted as secondary evidence because trajectory error also includes:

- Initial-state error.
- Numerical integration error.
- Mass and inertia mismatch.
- Wind estimation error.
- Timing mismatch.
- Actuator and control-delay mismatch.

### 3. Optional Experiment: Shared Closed-Loop Controller

A shared PX4-like or path-tracking controller can be connected to both simulation backends. The controller then generates actions from each simulated state, and the resulting closed-loop trajectories are compared.

This is useful for evaluating whether a model is a better simulation backend for controller development. It is not the cleanest evidence for aerodynamic model accuracy because the controller can compensate for model errors and the two models will quickly experience different states and controls.

## Recommended Main Claim

The paper should primarily claim improvement from the teacher-forced one-step wrench comparison. The short-horizon rollout should be used as supporting evidence that the improved wrench estimate also improves trajectory prediction.

A cautious wording is:

> We compare the learned estimator and the DeLaurier-based model through a common body-frame wrench interface. Although their internal outputs differ, both models are reduced to the net force and moment applied to the vehicle base. Both are evaluated using the same recorded flight states and actuator commands, avoiding controller-induced differences. The learned model is then tested both as a one-step wrench predictor and as a short-horizon open-loop dynamics model.

## How to Feed Control Signals

For the main comparison, control inputs should be replayed from the real flight log, not regenerated by a controller.

The required inputs include:

- Flapping phase or corrected phase.
- Wing stroke angle.
- Flapping frequency.
- Motor command.
- Left elevon command.
- Right elevon command.
- Rudder command.
- Body velocity or relative air velocity.
- Airspeed and density.
- Wind estimate, if available.
- Attitude or body-frame gravity vector.

Using recorded controls avoids an unfair comparison where different model trajectories lead to different controller outputs.

## How to Connect the Neural Model to IsaacLab

The learned model should be added as a separate aerodynamic backend, not added on top of the current DeLaurier model.

The intended backend options are:

```text
aero_backend = "delaurier"
aero_backend = "learned_effective_wrench"
aero_backend = "hybrid_residual"
```

The first implementation should use `learned_effective_wrench`, where the neural network directly outputs the total body-frame wrench.

If the neural model predicts total effective wrench, the simulator must disable the DeLaurier wing model, tail aerodynamic model, and fuselage drag for that backend. Otherwise, the same aerodynamic effects would be counted twice.

A hybrid residual backend is possible, but it should only be used if the training target is changed to:

```text
residual_wrench = real_effective_wrench - DeLaurier_predicted_wrench
```

This is a different modeling problem and should not be mixed with the current total-wrench estimator.

## Implementation Risks

### Coordinate Frames

All comparisons must use the same body-frame convention. The IsaacLab-applied wrench and the real-flight effective-wrench labels must agree on:

- Body x direction.
- Body y direction.
- Body z direction.
- Moment sign convention.
- Moment reference point.

### Time Alignment

The learned model is sensitive to phase and recent history. Phase, actuator commands, state estimates, and target labels must be aligned by timestamp. A small phase shift can create a large wingbeat-scale force error.

### Causal History

If the selected neural model is a causal temporal model, online inference in IsaacLab must maintain a history buffer. Feeding only the current frame would not match the trained model.

### Environment Compatibility

The training project uses the `flap-train-gpu` conda environment, while IsaacLab uses `env_isaaclab`. For simulation integration, the inference code should be packaged so that IsaacLab can load the trained model without importing unnecessary training-only dependencies.

Possible options:

- Export a minimal PyTorch inference module and load `model_bundle.pt`.
- Export TorchScript or ONNX if dependency isolation becomes difficult.
- Keep the first comparison offline, using the training project to predict on logged data, before integrating online inference into IsaacLab.

### Meaning of Effective Wrench

The learned target is an effective wrench reconstructed from flight logs. It may include real aerodynamic loads, body drag, unmodeled actuator dynamics, wind effects, and residual state-estimation errors. The paper should not describe it as a pure aerodynamic coefficient model.

### DeLaurier Baseline Interpretation

The DeLaurier model should be described as a literature-based physics baseline. It is not trained on the same logs. Therefore, if the learned model performs better, the conclusion should be that real-flight data improves effective wrench prediction under the tested flight conditions, not that the DeLaurier theory is generally invalid.

## Suggested Paper Structure

### Methods Section

Add a subsection such as:

```text
Physics-Model and Learned Effective-Wrench Comparison
```

Key points:

- The two models have different internal outputs.
- Both are converted to a common body-frame net wrench.
- The same recorded states and actuator commands are used.
- The learned estimator predicts total effective wrench.
- The DeLaurier model is evaluated as a physics baseline.

### Experiments Section

Add two protocols:

1. Teacher-forced wrench prediction on held-out logs.
2. Short-horizon open-loop rollout from real initial states.

For the one-step comparison, report per-axis wrench metrics. For rollout, report trajectory and attitude errors over short horizons.

### Results Section

Use two tables:

1. Wrench prediction comparison:

```text
Model | RMSE_Fx | RMSE_Fy | RMSE_Fz | RMSE_Mx | RMSE_My | RMSE_Mz | Mean R2
```

2. Short-horizon rollout comparison:

```text
Model | Horizon | Position Error | Velocity Error | Attitude Error | Angular-Rate Error
```

Add representative plots:

- Predicted vs. inferred wrench for selected held-out logs.
- Short-horizon rollout overlays against real trajectory.
- Per-axis residual distributions.

## Recommended First Implementation Step

Start with offline teacher-forced evaluation on the held-out test logs.

This avoids the complexity of online IsaacLab integration and directly answers whether the learned model predicts the real-flight effective wrench better than the DeLaurier baseline.

After the offline comparison is working and the coordinate conventions are verified, implement the learned model as an IsaacLab aerodynamic backend for short-horizon rollout experiments.
