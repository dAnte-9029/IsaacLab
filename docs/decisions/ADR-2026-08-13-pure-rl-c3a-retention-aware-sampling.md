# ADR-2026-08-13: Retention-aware task sampling for PureRL C3a

- Status: Experimental
- Date: 2026-08-13
- Scope: C1/C2c/C3a rehearsal allocation on the measured CPU-native plant

## Context

Fixed C3a rehearsal mixtures and actor-only distillation did not preserve every previously promoted behavior.
Increasing one old-task quota before training also cannot react when the weakest ability changes during a run.
PPO should remain on-policy, so stale trajectory replay is outside this experiment.

## Decision

Add a default-disabled C3a scheduler that changes the number of environments assigned to C1, exact C2c rehearsal,
and current C3a turns. It uses only completed episodes generated by the current policy. The retained signals are C1
survival plus tail-action limit occupancy, strong-climb C2c recovery, and C3a event completion without termination.

The scheduler starts from the accepted `15/35/50` percent mixture, keeps minima of `10/25/30` percent, updates no
more often than every 1200 policy steps, requires at least 16 completed episodes per ability, and limits each family
change to 5 percentage points. Success-rate targets are `98/95/95` percent. Signals use an EMA with coefficient
`0.3`. Strong-climb probability starts at `0.50`, remains within `0.50--0.85`, and changes by at most 0.10 per
update. When no deficit remains, probabilities move back toward the accepted baseline.

The first controlled run starts weights-only from the promoted C2c `model_550.pt`, uses actor distillation
coefficient `0.05`, 256 environments, 16 mini-batches, 100 PPO iterations, and seed 0. Fixed evaluation grids and
promotion gates remain unchanged.

## Consequences

- PPO rollouts remain on-policy; only future reset assignments change.
- The plant, reward, observation, action, critic, and fixed evaluation contracts are unchanged.
- Telemetry records the active probabilities, EMA retention signals, and scheduler update count.
- C3b and C3c reject this experimental option until C3a evidence justifies extending it.

## Validation requirements

- Pure tests must cover probability normalization, minima, bounded changes, and return toward baseline.
- Launcher tests must prove that the feature is explicit and C3a-only.
- A CPU-native runtime test must execute an adaptive update and report finite observations and rewards.
- The background training process must load the declared C2c checkpoint and enter PPO iteration without errors.
